Key design choices

  • Stateless backend sessions: every protected request carries a JWT.
  • Versioned REST API at /api/v1.
  • Postgres schema is controlled by Flyway, with Hibernate set to validate.
  • Frontend is deployable as static assets; API and database scale separately.

Security boundaries

  • Only health, auth, public tutors, public enquiries, uploads, and Google callback/status routes are open.
  • Services use authenticated tutor ownership checks before reading or mutating private records.
  • Secrets are environment variables: database credentials, JWT secret, Google OAuth settings.

Operational notes

  • Render health checks hit /api/v1/health.
  • Database pool size is env configurable through Hikari settings.
  • Render free-tier cold starts are reduced by the keep-awake GitHub workflow.
  • Local seed data can reset and repopulate the development database.

Scaling path

  • Move profile images to durable object storage if local API disk is not persistent.
  • Add background jobs for calendar sync if request-time sync becomes slow.
  • Add API rate limiting and audit logs before broader public beta traffic.

Data Model

The database is created by Flyway. Core ownership is simple: a users row owns one tutor profile and many students, lessons, imported earnings, and calendar settings.

users

Account root: email, password hash, role. Referenced as tutor owner by many tables.

tutor_profiles

One per user. Public search uses is_public, slug, location, online flag, and teaching details.

students

Many per tutor. Lessons reference students, and enquiries can be converted into student records.

lessons

Many per tutor and student. Stores timing, rate, lesson/payment status, notes, links, and Google event metadata.

lesson_series

Recurring lesson template. Individual lessons can point back to the series.

enquiries

Created from public tutor pages and linked to a tutor profile.

imported_earnings

Historical weekly income rows merged into analytics.

google_calendar_connections

OAuth tokens and sync preferences for a tutor.

uploads

Profile image URLs are stored on tutor profiles and served from /uploads/**.

Where Do I Change This?

Use this as a first stop before diving into search. The naming is consistent enough that related files sit close together.

Tutor search filters

Start in the public search page and the tutor API pair.

  • frontend/src/pages/public/TutorSearchPage.tsx
  • frontend/src/api/tutorApi.ts
  • PublicTutorController and TutorProfileService

Lesson behavior

Most lesson rules live in the service; UI form/table parts are split under the lessons folder.

  • frontend/src/pages/dashboard/LessonsPage.tsx
  • frontend/src/pages/dashboard/lessons/*
  • LessonController, LessonService, LessonRepository

Profile editing

Profile fields need matching TypeScript types, DTOs, entity fields, and Flyway migrations when persisted.

  • frontend/src/pages/dashboard/ProfileSettingsPage.tsx
  • frontend/src/types/tutor.ts
  • TutorDtos, TutorProfile, migrations

Auth and route protection

Frontend gates protected pages; backend security decides which URLs are public.

  • frontend/src/components/layout/ProtectedRoute.tsx
  • frontend/src/api/authApi.ts
  • SecurityConfig, JwtAuthenticationFilter, AuthService

Analytics and earnings

Dashboard display, CSV import/export, and revenue periods are grouped by analytics.

  • frontend/src/pages/dashboard/EarningsPage.tsx
  • frontend/src/api/analyticsApi.ts
  • AnalyticsController, AnalyticsService

Database changes

Add a new numbered Flyway migration. Keep DTOs, entities, frontend types, and seed data in sync.

  • backend/src/main/resources/db/migration
  • backend/scripts/seed-local-data.sql
  • frontend/src/types

Runbook

Local startup

  • docker compose up -d starts PostgreSQL.
  • cd backend && SPRING_PROFILES_ACTIVE=local ./mvnw spring-boot:run starts the API.
  • cd frontend && npm install && npm run dev starts Vite.
  • ./backend/scripts/seed-local-db.sh loads demo data after Postgres is running.

Verification commands

  • cd backend && ./mvnw test compiles and tests the Spring Boot app.
  • cd frontend && npm run build type-checks and builds the React app.
  • GET http://localhost:8080/api/v1/health checks the backend health endpoint.
